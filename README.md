# Uplift Modeling for Retention Outreach

Predicts which customers will stay **because** they are contacted, not just which customers are likely to
leave. Retention budget then goes to customers outreach actually helps, instead of customers who would stay
(or leave) anyway.

The model is a **T-Learner**: two models predict each customer's chance of staying with and without outreach,
and the difference is their **uplift score**. A Streamlit dashboard turns the scores into a ranked call list,
explanations and an ROI planner.

## Quick start

```bash
pip install -r requirements.txt
python run_pipeline.py          # builds all outputs (~5 min)
streamlit run dashboard.py      # opens the dashboard in your browser
```

## Key terms

| Term | Meaning |
|---|---|
| **Uplift score** | How much outreach raises a customer's chance of staying. +30 pts = about 30 more customers kept per 100 like them who are contacted. |
| **Priority group** | Customers split into five equal groups by uplift score; Priority 1 benefits most. |
| **Observed vs predicted** | Predicted comes from the model; observed is measured from real outcomes (contacted vs not-contacted customers). |
| **Net benefit** | Extra customers kept × value per customer, minus contact cost. |
| **ROI** | Net benefit ÷ cost. 100% = every $1 spent comes back as $2. |
| **Break-even uplift** | Cost ÷ value ($20 ÷ $300 = 6.7 pts). Contacting a customer below this costs more than it returns. |

Uplift modeling separates four kinds of customer: **persuadables** (stay only if contacted, the target),
**sure things** and **lost causes** (contact changes nothing), and **sleeping dogs** (contact makes them
leave). Churn-risk targeting cannot tell these apart; at 30% outreach it contacts 108 sleeping dogs, the
uplift model 3.

## Assumptions

- **Data:** 10,000 customers from the Kaggle bank churn dataset. Engagement score, login frequency, purchase
  count, support tickets, past campaign response, treatment and outcome were generated by `generate_dataset.py`.
- **Randomized outreach:** about half of customers were contacted at random, so retention differences can be
  credited to outreach. Contacting one customer does not affect another.
- **Honest scores:** every customer is scored by a model that never saw them (5-fold cross-validation).
- **ROI:** $20 per contact and $300 per customer kept are placeholders, the same for every customer, with no
  capacity limit. Change them in `roi.py` or in the dashboard's campaign planner.
- **Reproducibility:** all random steps use fixed seeds; package versions are in `requirements.txt`.

## Limitations

- **Synthetic treatment effect.** The true effect of outreach was written into `generate_dataset.py`, so the
  model recovers rules we defined. Expect weaker results on real data; dollar figures show how the method
  works, not expected revenue.
- **Averages, not guarantees.** A score describes customers like this one, not what one person will do.
- **SHAP shows patterns, not causes.** It explains how the model scores customers, not why they stay.
- **Two models for scoring and explaining.** Rankings use out-of-sample scores; SHAP explains a model trained
  on all customers. They agree closely (correlation 0.98, average gap 1.5 pts) but not exactly.
- **One kind of outreach.** The data cannot say which channel or offer works best.
- **Library versions.** Random Forest results can shift slightly between versions; the selected model does not.

**Before using this for a real campaign:** use real costs and customer values, train on randomized campaign
data only, keep a random uncontacted group to measure the true effect, review targeting by age or country
for fairness, and retrain as behavior changes.
